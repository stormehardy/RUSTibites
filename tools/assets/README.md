# tools/assets — The Bibites asset extraction pipeline (task-76)

Extracts the installed game's art (textures, sprites, procedural CSV data, fonts, materials, prefab
hierarchies) and captures in-world reference frames (historical lol captures; canonical default world is testdata/real/Default.zip), writing everything under the **tracked** repo
directory `assets/game/` (game art is not MIT — see `assets/game/LICENSE-ASSETS.txt`).

## Requirements

* Python with **UnityPy 1.25.4** + Pillow (already installed in this environment).
* Read-only access to the installed game data:
  `C:\Program Files (x86)\Steam\steamapps\common\The Bibites\The Bibites_Data`
* For `capture_reference.py`: the BibitesAPI checkout (`BIBITES_API_HOME`, default
  `C:\Users\Storme\Desktop\Projects\BibitesInfo\BibitesAPI`) and the game installed. The game is started
  **hidden** (`window="hidden"`); screenshots come from the bridge's offscreen RenderTexture. Never open
  a visible window for this pipeline (see `docs/HEADLESS_POLICY.md`).
* No plugin is required or deployed by these scripts; `extract.py`/`prefab_dump.py` only read asset
  files, never launch the game.

## Scripts

| script | writes | what it does |
|---|---|---|
| `extract.py` | `assets/game/{manifest.json,sheets,sprites,text,fonts,materials,ui}` | UnityPy dump of `resources.assets`, `sharedassets0-3.assets`, `gameglobalgamemanagers.assets`, `level0-4`: every Texture2D (PNG, alpha), every Sprite (decoded PNG + exact `rect`/`pivot`/`pixels_per_unit`/9-slice `border`), the 5 procedural TextAssets (`parameters`, `bibites_parts`, `bibites_sizes`, `egg_sizes`, `pellet_sizes`) as CSV under `text/` with logical manifest keys, Fonts (TTF bytes + metrics), Materials (serialized colours/floats/texture properties), UI sprites/textures per asset file, and a parsed `procedural` block. `--list` enumerates without writing. |
| `prefab_dump.py` | `assets/game/prefabs.json` | best-effort UnityPy walk of the in-world prefab roots (bibite, egg, plant/meat pellet, Zone, Radiation Tower, ColorKiller, PheroTower, FieldOfViewDisplay, background): child Transform local position/rotation/scale, SpriteRenderer sorting order/layer, colour, flip flags, resolved sprite name. MonoBehaviour-only components are unreadable without script typetrees and are reported as such. |
| `contact_sheets.py` | `assets/game/contact_sheets/*.png` | human-review grids for every decoded world sprite, every sheet texture and every UI sprite (`contact_sheets.json` lists counts). |
| `coverage.py` | `assets/game/coverage.json` | coverage gate: procedural part sheets / object sprites / parameters vs extracted textures, prefab roots with readable renderers, Here/ renderer and UI asset-name references, 9-slice counts, font/material stats and known gaps. Prints the in-world percentage (currently **94.1%**, target ≥90%). |
| `capture_reference.py` | `assets/game/reference/*.png`, `reference.json`, `reference/README.md` | starts the game hidden, loads the real lol save read-only, takes camera-controlled in-world frames (full world, population, zone/pellets/eggs, bibite close-up) via `POST /camera` + `GET /screenshot`, records camera centre/orthographic size/world state in the README + JSON, stops the game in `finally`. |
| `check_ui_coverage.py` | — (spec-dev's checker) | `python tools/assets/check_ui_coverage.py --strict`; 0 required gaps after the `ui.materials.color_spectrum` alias landed. |

## Notes on correctness

* Sprite geometry is read from the **Sprite object itself** (`m_Rect`, `m_Pivot`, `m_PixelsToUnits`,
  `m_Border`) with UnityPy 1.25.4; the texture reference is `sprite.m_RD.texture`. This is exact rect/
  pivot/PPU and 9-slice border data, not guessed grid slicing. Sheets are still exported too, so a
  uniform-grid renderer (`parts` rows/cols) works without per-frame sprite PNGs.
* The procedural CSVs use a **comma decimal** in the shipped build (`0,55`); the raw files are preserved
  byte-for-byte and `manifest.procedural` provides parsed float maps.
* The game strips Shader asset names; materials keep `shader_<PathID>` and their serialized properties
  (`_Color`, `_hue`, `_offset`, …). UI material aliases are exposed at `manifest.ui.materials`
  (`color_spectrum` → `rainbowMaterial`, `skin_recolorizer`, `eye_recolorizer`, `field_of_view`).
* Re-running `extract.py` is deterministic for the same game build; the manifest is regenerated and the
  companion files (`prefabs.json`, `reference/`) are attached if present. Reference frames are only
  regenerated by `capture_reference.py`.
* Writes only under `assets/game/`; temporary probe files were kept under `target/` (gitignored).
