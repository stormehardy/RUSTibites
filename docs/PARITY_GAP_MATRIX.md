# Parity gap matrix - game vs RUSTibites (0.6.3.1, canonical Default)

> **Reliability warning (2026-11-03).** Read-only audits that compared the decompiled C# in `Here/` line by line with the Rust code found
> many rows below labelled `implemented`/`PASS` that were wrong or missing (e.g. one-attack-per-tick, pheromone cost scaling,
> `attackedDmg` decay, FOV query region, hatch orientation, species membership, pellet decay save format, absolute zone sizes) and a UI
> whose inspector/editor/lineage/graph panels were placeholders. The source-derived findings, what was fixed and what is still open are in
> [`PARITY_AUDIT_SOURCE.md`](PARITY_AUDIT_SOURCE.md) (simulation, save/load, challenges) and [`PARITY_AUDIT_UI.md`](PARITY_AUDIT_UI.md)
> (viewer). Treat the status columns below as unverified unless a row cites one of those documents.

**Status:** living audit / prioritised gap list (task-134 follow-up, 2026-10-30). **Owner:** spec-dev.
**Purpose:** enumerate the systems in the decompiled game (`Here/`) and the four subsystem specs, mark
what RUSTibites implements, and rank the remaining work for the final parity pushes. Feature owners fix
from this list; this document does not replace the specs or `docs/DEVIATIONS.md`.
**Canonical world:** `testdata/real/Default.zip` (`docs/TESTING_POLICY.md`). Ring/lol/special saves are
historical fixtures and are named as such below. **Game version:** The Bibites 0.6.3.1 / Unity
6000.0.44f1 (`Here/`, installed build).
**Executable verification:** [`PARITY_ACCEPTANCE.md`](PARITY_ACCEPTANCE.md) runs the headless checks and
records PASS/FAIL/UNVERIFIED for every row below; update both files together when evidence changes.

This is a **static audit plus the currently committed evidence**, not a claim that every row has a live
game capture. Status vocabulary:

| Status | Meaning |
|---|---|
| `implemented` | Code follows the spec contract and has representative tests; where marked in Evidence, an end-to-end parity/capture gate also passes. |
| `partial` | Code exists but has a known gap, is only unit-tested, or lacks an end-to-end parity fixture. |
| `missing` | No implementation (or only a schema/model stub). |
| `intentional` | Deliberate divergence/non-goal recorded in `docs/DEVIATIONS.md` or `docs/design/UI_PARITY.md`. |

**Priority:** `P0` = blocks a claimed simulation/parity guarantee or the main visual acceptance;
`P1` = important compatibility/visual surface with a known gap; `P2` = secondary/edge feature;
`P3` = cosmetic or intentional non-goal. **`needs parity fixture`** means no game-side measurement exists
yet for that row.

Evidence tags used below: `unit` = Rust tests; `R` = Ring game-vs-Rust parity capture
(`testdata/parity/captures/ring_seed12345/pass-0` vs `testdata/parity/rust_ring`, `compare.py --profile
default`); `D` = official Default fixture (`testdata/parity/default/official_{game,rust}_{600,3000}`,
`official_analysis_{600,3000}.json`); `C` = targeted capture experiment under
`testdata/parity/experiments/` (gitignored); `U` = viewer/HUD A/B evidence (`docs/VIEWER.md`); `F` =
format/compat/checkpoint/bench evidence. All game-data artifacts are local-only/gitignored.
