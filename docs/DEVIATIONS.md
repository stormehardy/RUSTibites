# Fidelity deviations and accepted quirks

This is the authoritative running list of places where RUSTibites intentionally
differs from the installed game (0.6.3.1), and of game quirks we deliberately
reproduce. Every entry states the decision and the reason.

When the specification and the game disagree, the game's **compiled behaviour**
wins; when the game's behaviour is undefined or a bug that would corrupt state,
we fix it and record the divergence here.

## A. Intentional divergences

| # | Area | Game behaviour | RUSTibites behaviour | Reason |
|---|---|---|---|---|
| D1 | Physics | Unity Box2D solver, capsules/boxes, contacts | Purpose-built 2D solver using the captured Box2D/Physics2D constants (gravity 0, velocity iterations 5, position iterations 3, contact offset 0.01, bounce threshold 1, max translation/rotation 100/360, Baumgarte 0.2, captured layer matrix and PhysicsMaterial2D pairs) | Determinism, speed, no Box2D dependency |
| D2 | Physics contact detail | Box2D manifold details, sub-stepping, sleeping, multiple contact points | Single contact point per pair; no sleeping; no box–box; capsule–box closest point via a deterministic 32-step ternary search; linear slop assumed 0.005 (`ASSUMPTION(BOX2D)`) | Not exposed by the game; negligible at this scale |
| D3 | Update timing | `Update()`s, coroutines, FPS governor can shrink `Time.fixedDeltaTime` during load | Fixed `dt = 1/sim_tps` for the whole run; no wall-clock coupling; 30 TPS default, overridden by save/scenario settings | Headless determinism; the game's steady state is the same |
| D4 | Randomness | Two RNG families: unseeded `System.Random` instances + global `UnityEngine.Random` | One deterministic `Rng` (xoshiro256\*\*) with per-entity derived streams | Reproducibility. Mutation *outcomes* are therefore validated statistically, not bitwise |
| D5 | Mutation outcomes | Depend on unseeded .NET randomness and draw order | Deterministic given seed; formulas, ranges, Poisson counts and clamps exact | Same as D4 |
| D6 | Destruction | `Object.Destroy` deferred to end of frame; destroyed pellets/spots can still be found by later phases in the same tick | Immediate logical removal at the defined phase boundary | Avoids ghost references and order-dependent bugs; documented in the tick pipeline |
| D7 | FOV held pellets | `PelletIsHeld` mutates the held list during vision, silently dropping grabs | Held pellets are excluded from FOV without mutating grab state | Game bug that corrupts mouth bookkeeping; behaviour otherwise equivalent |
| D8 | ColorKiller scan | Can walk stale colliders from a reused 128-entry buffer | Bounded correct scan | Undefined behaviour in the game; keep-the-band polarity reproduced |
| D9 | Species template | `Species.template` aliases live gene/node/synapse arrays | Deep snapshot of genome + brain | Aliasing can observe live runtime state; snapshots are behaviourally equivalent for the distance metric |
| D10 | Species naming | (closed 2026-11-15) The Latin words live in the game's `Resources/Patrons/patreon_supporters` asset, not in the decompiled source | None now: `tools/extract_latin_names.py` reads the asset (866 words, in the game's order, the `latinized` column only) into `crates/bibites-core/src/latin_names.rs`, and the namer draws from it as `SpeciesNameGenerator` does; loaded species names are preserved on round-trip | Cosmetic only; the draws of the port's own name stream differ from the game's (Unity's `Random`) |
| D11 | `data.bin` history | Nested LogLike compressed statistics streams written by the game | Since 2026-11-06 the Graphs streams, the bibite tracker, the species logs and the zone logs are read and regenerated by the core (`datalog.rs`, `data_bin.rs`; game versions 0.6.0a9 / 0.6.0a15 / 0.6.0a10 and later; see `PARITY_REMAINING.md`). Still carried as loaded: the genes stream (the Gene Analysis buckets) and, in older saves, whole blocks the core does not read. Before that it was an opaque pass-through | The histories do not affect the simulation; they are what the Graphs and Lineage panels plot |
| D12 | User settings | Some user-level settings affect behaviour (e.g. easter eggs) | Out of scope for M1; defaults used (disabled) | Headless engine has no user profile |
| D13 | Saves | 0.6.3.3+ / 0.6.4a1 folder-save layout (`sim.info` + `saves/_00.zip`) | `Unsupported` error with a clear message | Not present in the decompiled installed build; future work |
| D14 | Old genomes | Migration of pre-0.6a1 alpha files | Best effort; clear `Unsupported` error rather than corrupted state | Very old formats, low value |
| D15 | Renderer/UI/audio | Unity scenes, sprites, UI | Not implemented (headless milestone) | Milestone 1 is the simulation engine |
| D16 | Frame-rate-dependent entity phase offsets | Derived from `UnityEngine.Random` draws at birth | Derived from per-entity RNG streams | Reproducibility (D4) |
| D17 | Cheat/easter-egg flags | Rare random radiation/rain/killer/source flags at birth | Same probability rules where known; user-level gate defaults off | M1 scope |
| D18 | Pellet production RNG | Pellet sizes/positions use unseeded `System.Random`/`UnityEngine.Random` per zone | Deterministic per-zone streams; pellet counts/biomass therefore diverge statistically from a game run | Reproducibility (D4); the parity `default` profile compares pellet curves within tolerance, not exactly |
| D19 | Physics trajectories | Box2D trajectories vs custom solver | Position/velocity diverge after the first ticks; genetics/brain/senses/energy accounting remain exact while behaviour is identical | Speed/portability (D1); the parity harness reports positions as informational and gates by distributions/curves |
| D21 | Order of physics bodies whose boxes start at exactly the same x | Not applicable (Box2D has its own broadphase) | The broadphase sweeps the bodies in the order (start of the box, body index): a total order, the same however it is sorted (from scratch on the pool, or repaired from the last tick). Before 2026-11-05 equal starts were ordered by whatever the serial sort algorithm did with them | A total order lets the sort run on the pool and lets pellets at rest stay out of the step (`pellet_sleep`). It changes results only for two bodies that start at the same x *and* are near each other: measured 1 such pair in 63,760 overlapping pairs in Big Pellet, 2 in 189,726 with 20,000 bibites, 0 in 202,249 with 2,000 bibites. The owner agreed on 2026-11-05; the ignored evolution regression fingerprint moved with it |
| D20 | Fresh-scenario virgin spawner identity | Game spawner uses unseeded `System.Random`/`UnityEngine.Random` for spawn positions/orientations | Counts and cadence are structural (1 at t=0, then 1/s until the row minimum); positions/orientations use seeded RNG streams, so per-entity identity differs | Reproducibility (D4); Ring-save parity is unaffected because save-load never resumes the virgin spawner |

## B. Game quirks reproduced deliberately

These look like bugs but affect ecology or save compatibility, so they are
replicated (marked in code with `// QUIRK:` comments and in the specs):

| # | Quirk | Why reproduce |
|---|---|---|
| Q1 | 10-second lag on zone `pelletBiomass` recount (counters update only on spawn/recycle/recount, not on eating) | Changes spawn overshoot and vegetation dynamics |
| Q2 | Pheromone decay is 0.25 u²/s in 0.25 s quanta (not the 1 u²/s stated in tooltips/secondary docs) | Compiled code is authoritative; **confirmed by capture** 2026-10-29 (`testdata/parity/experiments/phero_decay`): −0.25 u²/s in 0.25 s quanta (−0.0625 per quantum); a 4 s window lost exactly 1.0; spot destroyed at ≤0 |
| Q3 | ColorKiller kills hue-distance **≥** tolerance (keeps the band), opposite to the community-guide wording | Compiled branch; **CONFIRMED by capture** 2026-10-29 (5/5 cases incl. an inverted band: red at distance 0.33 died, blue at 0.17 survived). Keep-the-band — do not flip (evidence `testdata/parity/experiments/color_killer_polarity`) |
| Q4 | Pheromone headings are lost on save/load (`heading: {}`); radiation dose is transient and not persisted | Save-file compatibility and identical reload behaviour; **confirmed by capture** 2026-10-29 (`testdata/parity/experiments/phero_decay`, save→load→save keeps `heading: {}` while strengths round-trip) |
| Q5 | Pellets spawned by deaths/producers are not owned by a zone and never recycled by it | Affects long-run pellet budget |
| Q6 | `Pherosense` inverse-distance sums are not size-scaled | Compiled code |
| Q7 | `IsGrabbing` brain input is the held-object count (0..10), not a 0/1 flag; `Maturity` is raw growth | Compiled code; tooltip mismatch documented |
| Q8 | Mutation input-pick never selects the last input (`Random.Range(0, NInputs-1)`) | Distribution parity |
| Q9 | Egg/birth gene inheritance copies `is_mutant`, and speciation runs only at body birth/resume | Speciation state machine depends on it |
| Q10 | `GetInputIndex`-era off-by-one and mirrored sign labels | Behavioural parity; sign conventions are documented in the specs |
| Q11 | Collision damage uses the Box2D `ContactPoint2D.normal` sign; to be pinned down by capture before finalising `CollisionSign` | **CONFIRMED by capture** 2026-10-29 (`testdata/parity/experiments/collision_sign`): both collision partners are damaged on the same impact, each with a POSITIVE approach speed; damage = `(num2 − threshold) × constant` with `num2 = 2·m_other·closing/(m_other+m_this)`. Measured with equal masses: closing 100 → 5.0 damage to BOTH bodies, closing 200 → 15.0 to BOTH, reversed roles symmetric. Body mass weighting not captured (bridge cannot read/set mass — see `docs/PARITY.md` Appendix A2 for the minimal plugin hook) |

## C. Open fidelity questions (tracked in specs + parity harness)

**Status: closed (task-18, 2026-10-29).** Q2, Q3, Q4 and Q11 are settled: each was re-measured against
the installed game with the parity harness rather than inferred from source, the answers are recorded inline
in the table above, and the full methods/tables are in `docs/PARITY.md` Appendix A. Evidence (gitignored):
`testdata/parity/experiments/phero_decay/manifest.json` (Q2 decay quantum, Q4 heading loss),
`.../color_killer_polarity/manifest.json` (Q3 predicate: kill iff hue-distance >= tolerance, do not flip),
`.../collision_sign/manifest.json` (Q11 approach-positive for both partners, both bodies damaged,
`damage = (num2 - threshold) * constant`). No code decisions remain open from these four; the only residual
sub-item is the collision-damage *body-mass weight* (the formula above is spec-implemented, but the bridge
cannot read/set bibite mass, so that term is not capture-verified — the optional hook is described in
`docs/PARITY.md` Appendix A2 and must not be built unless validation needs it).

1. RESOLVED: ColorKiller polarity — kill iff hue-distance ≥ tolerance (keep-the-band), confirmed by capture (see Q3, `testdata/parity/experiments/color_killer_polarity`).
2. RESOLVED: collision damage normal sign — approach-positive for both partners; both bodies take damage (see Q11, `testdata/parity/experiments/collision_sign`). Open sub-item: body-mass weighting term (needs the plugin hook in Appendix A2).
3. Exact `System.Random` call order for mutations — only relevant if we later choose bit-exact mutation parity.
4. Body-mass weighting in collision damage — the compiled formula is known, but the bridge cannot set/read bibite mass; needs `GET /d/bodies` + `POST /d/mass` in the parity plugin (`docs/PARITY.md` Appendix A2).
5. `data.bin` regeneration — done for the Graphs streams, the tracker, the species and the zone logs; the genes stream (hourly gene buckets) is still carried as loaded.

## Known internal inconsistencies (not game deviations)

These are places where two parts of RUSTibites hold different copies of a captured constant. They are
harmless on the current code paths (one copy is authoritative at runtime) but should be aligned before
a new consumer starts using the other copy.

| # | Item | Detail |
|---|---|---|
| I1 | Material default decay parameters duplicated | `settings.rs::MaterialSetting` carries the captured runtime prefab values for non-decaying materials (Plant `fresh_time 100`, `decay_rate 0.005`; Fat/Armor `1000`, `0.02`), while `pellet.rs::MaterialProperties::{PLANT,FAT,ARMOR}` duplicate the same structs with `fresh_time/decay_rate = 0.0`. Runtime materials come from `SimSettings`, so simulation behaviour is correct; if a path ever builds pellets from `MaterialProperties` defaults directly, decay settings would differ. Align to the `settings.rs` values (source of truth) when touching either table. |

Add an entry here (and to `docs/ARCHITECTURE.md` §14) whenever a deliberate
deviation is introduced.

## Template tolerance (task-44)

Real user template folders contain files the game loads but a strict NEAT parser rejects. The io template path now mirrors the game's repairs: node Index fields are re-mapped to array positions (synapse endpoints follow the declared-index map), -1 synapse endpoints are dropped, duplicate synapse innovations are accepted, and short pre-0.6a1 gene arrays (28/34 values) are zero-padded to the 34-value layout before the normal migration. Tolerant loading is the default for templates (scenario spawner/CLI); rom_json remains strict for validation tests. Tolerant loads are re-emitted canonically at 0.6.3.1 (the original JSON is not byte-preserved). Verified on the 220-file real user folder: strict 215/220 -> tolerant 220/220; the game's own /bibite/upgrade accepts the previously rejected samples (including 0.5-era short-gene files, updated=true).
